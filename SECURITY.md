# Security Policy

## Supported state

The current release candidate is a local, read-only scaffold using deterministic mock data. Real adapters and remote exposure are not implemented.

## Reporting

Do not publish sensitive reports in a public issue. Report privately to `oneflawlessstudio@gmail.com` with the affected commit, reproduction steps, observed impact and sanitized logs.

Response timing is best effort; no contractual service level is claimed.

## Current controls

- No credential is required by the scaffold.
- Local environment files are excluded from version control.
- Status data is generated by a deterministic mock provider.
- Runtime features are explicit and default to disabled unless enabled in code.
- Content access, adapter calls, state changes and paid services are disabled.
- Runtime boundaries are covered by automated tests.
- Dependency auditing is a blocking CI gate.

## Future adapter requirements

Before an adapter is enabled, add and validate:

- a documented local trust boundary;
- least-privilege configuration;
- input and output validation;
- timeout, cancellation and safe failure;
- sensitive-value redaction;
- authorization and review checks;
- audit events;
- normal, error and unauthorized-path tests;
- recovery procedures.

Upstream issues in third-party tools should also be reported to their respective maintainers.
